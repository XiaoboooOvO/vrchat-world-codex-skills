# 坐标与朝向转换核验

适用于单个资产、路径、地标或整组场景对象；不要求模块化拆分，也不授权导入素材或修改场景。项目已有坐标合同优先于通用推断，项目常量留在项目合同中。

## 何时使用

- 坐标需跨文件、工具、地图、父子层级或世界空间换算。
- 导入后对象朝向、上下轴、镜像、位置或尺度异常。
- 需要从图像、平面图、锚点或路径恢复坐标和方位。

同一已知坐标系内的普通编辑可直接按现有合同处理。

## 工作流程

1. **锁定输入与目标。** 确认源资产及版本、目标场景/对象及其完整路径、导入文件和相关导出/导入设置。先核对活跃资产与正式合同；旧日志、截图和候选文件不能单独代表当前状态。若来源或场景版本不明，标为 `STALE` 或 `CONFLICTED`。

2. **明确每个坐标系。** 记录单位、轴顺序及正方向、左右手系、up/forward 轴、原点和 pivot。旋转还需说明所在平面、绕轴、零度方向、正方向、度/弧度、local/world 空间及北向基准（如适用）。区分有向 heading 与无向轴线；主轴本身通常不能区分相反的两个方向。

3. **列出完整变换链。** 分开记录源几何中已烘焙的变换、对象/root 变换、导出器轴转换、目标导入转换、Prefab/实例变换和每一级父节点变换。明确每一步的方向、公式及乘法约定，再组合成 source→target 变换。使用完整矩阵或明确的局部到世界转换；不要把不同轴或不同父级下的欧拉角直接相加。

   使用列向量时可写成 `p_T = T_{T←S} p_S`，复合关系为 `T_{C←A} = T_{C←B} T_{B←A}`。若工具采用其他约定，先说明其约定再计算。检查实际求值后的源变换及 parent-inverse；在 Unity 中检查整条父级链的 `localToWorld`，不要只读物体自身的 local rotation。

4. **按数据类型应用变换。** 点使用 `p' = A p + t`；方向向量不含平移，`d' = A d`；非均匀缩放下法线使用逆转置并归一化。分别核验对象原点、几何锚点、包围盒中心、质心、端口和边界，不要把不同定义的量互相当成同一目标。

5. **区分旋转与镜像。** 检查轴置换和线性变换的手性/行列式。行列式为负表示含镜像，不能用四元数或纯旋转替代；同时检查面绕序、法线和背面显示。不要用负缩放盲目补镜像。导入器设置相同也不能证明两个 FBX 的源轴向相同，应检查实际几何基向量。

6. **用有辨识力的探针核对。** 验证原点及源 `+X/+Y/+Z` 在目标空间的方向；用带明确 front/top/side 标记的非对称测试物，或至少两个独立且语义明确的锚点核对位置和朝向。道路/路径朝向用有序端点或切线确定，不能只靠主轴角。单独的包围盒、对象数、对称轮廓或可逆往返都不足以证明映射正确。

   从图像或平面图恢复坐标时，记录像素原点、行列方向、裁切/投影和标定点；未标定的截图只能提供方向线索，不能直接给出米制坐标。地理角度必须注明网格北、真北或磁北。

7. **核验与定位症状。** 按声明的独立锚点报告位置残差、角度残差和容差；方向异常时至少用顶视与侧视确认上下轴、镜像和倾倒问题。若几何与变换数据吻合、只有画面不对，再检查相机坐标、投影和视锥，避免先旋转模型。只对本次坐标结论提供证据，不把离线换算扩写成其他层级的验收。

8. **遇到矛盾就停。** 若合同、导入设置和探针不能同时成立，标记 `OPEN` 并指出缺少的源轴向、锚点、父级矩阵或版本信息。不要继续盲目枚举角度；先找出是哪一段变换未知或错误，并在授权范围内只修正一个明确的变换 owner。

## 角度表示

- 欧拉角仅在轴、顺序、空间和单位都明确时使用；计算优先用完整基向量/矩阵或四元数。
- 四元数只表示 proper rotation，不编码镜像或尺度。
- 绕错 pivot 会同时改变位置；记录旋转中心，并区分物体原点与网格几何原点。
- 任一单独的 `90°`、`180°` 或 `270°` 都不是完整变换合同。

## 精简记录

需要交付或复用映射时，记录：

```text
源资产/版本与目标场景/对象：
源/目标坐标系：单位、轴序与方向、手性、up/forward、原点/pivot：
导出/导入与已烘焙变换：
完整父级链及 source→target 变换/乘法约定：
角度基准与旋转表示：
独立锚点/轴向探针、位置与角度残差、容差：
证据层与状态：VERIFIED / OPEN / STALE / CONFLICTED：
假设与未决输入：
```

`VERIFIED` 只表示已识别的映射在上述探针和容差下有证据支持。若该任务不需要可复用记录，可在答复中简要说明源、目标、变换和未决项。
