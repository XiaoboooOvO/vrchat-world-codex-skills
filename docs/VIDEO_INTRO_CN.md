# 视频介绍草稿（中文）

建议长度：60–90 秒。

## 视频主线

1. **先展示问题（0–10 秒）**
   - Unity 世界项目容易出现职责混杂、层级难维护、修改误伤和验证过度承诺。

2. **展示设计 Skill（10–30 秒）**
   - 输入一个自然语言世界想法。
   - 输出玩家旅程、模块图、入口/出口、视线、交互面、语义层级和灰盒顺序。
   - 强调：先设计空间和职责，不直接创建 GameObject。

3. **展示构建 Skill（30–55 秒）**
   - 读取项目规则和当前状态。
   - 根据风险选择只读检查、源码修改或场景补丁。
   - 展示安全门、ProgramAsset、Undo、保存、编译和针对性验证。

4. **展示组合关系（55–75 秒）**

   ```text
   需求 -> 模块设计 -> 实现交接 -> Unity 安全修改 -> 证据验证
   ```

5. **说明边界并收尾（75–90 秒）**
   - 不默认启动 Play Mode、Build、上传或多人验收。
   - 它的目标不是替开发者做所有决定，而是让 AI 的决定更有边界、更容易检查。

## 旁白草稿

很多 VRChat 世界的问题，不是不会写脚本，而是一开始没有把空间、职责和修改边界想清楚。

这套 Skills 分成两部分。

第一个 Skill 负责设计：先描述玩家旅程，再拆成功能模块，定义入口、出口、视线、交互面、局部坐标和语义层级，最后形成可以交给 Unity 实现的模块计划。

第二个 Skill 负责安全实施：检查当前项目和 Git 状态，确认正确的 Unity 实例，根据任务风险选择最小工作流，并在修改场景时保留撤销、编译、保存和验证边界。

所以完整流程是：先设计模块，再安全地做进 Unity。它不会默认启动 Play Mode、Build 或上传，也不会把一次超时直接当成失败重试。

简单说，就是让 AI 不只是“改东西”，而是先理解这个世界应该怎么组织，再用可追踪、可恢复的方式完成修改。
